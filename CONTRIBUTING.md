# Contributing

Thanks for helping improve reaharness.

1. Use Node 22+ (`nvm use` if you have nvm).
2. `npm ci && npm run check` before opening a PR.
3. Keep PRs focused; match existing layering and naming.
4. Add or update tests for behavior changes.
5. Do not commit secrets, `dist/`, or `.reaharness/` session files.

Conventional Commit subjects are appreciated (`feat:`, `fix:`, `docs:`).
